# iHelp Ch02 开发记录

## 目标

给现有客服聊天入口增加 Function Calling 工具链，让模型在用户提问时自行决定调用哪个工具，并将工具结果回灌后继续流式作答。

## 完成内容

- FastAPI + SQLAlchemy 分层骨架。
- MySQL 数据库 `std_selfproject_db2`，四张表：`faq`、`conversations`、`messages`、`tickets`。
- 五个 LangChain `@tool` 工具。
- 工具注册、参数 Schema、超时重试、错误处理和结果回灌。
- `/api/chat` 接入单轮 Function Calling。
- 前端显示工具轨迹徽章。

- `conversations(id, user_name, status, created_at)`
- `messages(id, conversation_id, role, content, tool_name, tool_args, tool_call_id, created_at)`
- `tickets(ticket_id, conversation_id, description, ticket_type, status, created_at)`

## 工具清单

1. `query_order`：模拟订单查询
2. `query_product`：模拟商品查询
3. `query_logistics`：模拟物流查询
4. `query_faq`：SQL LIKE 查询 FAQ
5. `create_ticket`：写入人工工单

## Function Calling 流程

1. 模型先决定是否调用工具。
2. 若调用，只取第一个 `tool_call`，执行工具并回填 `ToolMessage`。
3. 工具执行前推送 `tool_status/running` 状态帧。
4. 工具执行后推送 `tool_status/success` 或 `tool_status/error` 状态帧。
5. 前端根据状态帧展示工具轨迹徽章。
6. 最终回答继续 SSE 流式输出。

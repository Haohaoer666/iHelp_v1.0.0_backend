# iHelp Ch05 开发记录

## Brainstorm 定稿

用户本轮关键原话：

- 要用 Superpowers 模式把客服系统升级成生产级架构：Workflow 确定性编排做骨架，主力 Agent 作为骨架里的核心节点。
- 先手写最裸的 Agent 循环，看清它就是带工具的循环，再用 LangGraph 重构。
- 图流程固定为：指代消解、意图识别、按意图分流、知识检索、置信度闸、主力 Agent、日志记录。
- 商品咨询和退款退货先检索；物流、订单、售后直接进 Agent；投诉不进 Agent 并提供转人工、建工单两个独立选项；闲聊不花模型调用。
- 转人工和建工单是两件事，前端各渲染一个独立按钮，后端不自动执行。
- 涉及具体库、框架、API 时先用 Context7 MCP 查最新官方文档。

确认的决策：

- 整体走 architectural 流程。
- 采用显式父图加显式 ReAct 子图，不使用 `create_react_agent` 隐藏循环。
- 持久化采用 LangGraph 官方 `AsyncSqliteSaver`，默认路径 `data/langgraph_checkpoints.db`，`session_id` 作为 `thread_id`。
- 业务数据继续写入现有 MySQL 审计表，SQLite 只负责 LangGraph checkpoint。
- 投诉路径固定给出两个独立动作选项。
- Agent 需要人工介入时只发送建议选项，不自动动作。
- 前端继续修改 `D:\std_selftest_frontend`。

Context7 核对：

- Context7 MCP `@upstash/context7-mcp` 版本 `4.1.1` 已启动。
- 已通过 `/langchain-ai/langgraph` 查询 StateGraph、条件边、`InMemorySaver`、`SqliteSaver`、`AsyncPostgresSaver`、`thread_id` 和 custom stream writer 的官方文档。
- 官方内建 checkpointer 不包含 MySQL；用户同意本章使用 `AsyncSqliteSaver`。

我产出的关键文件：

- 设计 spec：`docs/superpowers/specs/2026-09-18-ch05-production-workflow-design.md`

评审结论：

- 设计第 1 节父图、状态与数据流：用户确认。
- 设计第 2 节组件、接口与事件契约：用户确认。
- 设计第 3 节持久化、失败处理与运行控制：用户确认。
- 设计第 4 节验证、演示与前端验收：用户确认。

用户拒绝或纠偏：

翻车与返工：
